### Goals
- The trainee will understand the concept of tunneling and encapsulation
- The trainee will understand what a VPN is and when it is used
- The trainee will know the common tunneling and VPN protocols and the differences between them
- The trainee will know how to configure tunnels and a VPN between Linux machines

### Tasks
- Tunneling
  - What is tunneling? How is it related to encapsulation?
  - Why would you want to tunnel traffic? Give some common use cases
  - What is the "overhead" of a tunnel? How does tunneling affect the MTU, and why can it cause problems? (Read about MSS clamping)
  - What is the difference between a layer 2 tunnel and a layer 3 tunnel? Give an example for each one
  - Read about the following tunneling protocols, explain what each of them encapsulates and in what:
    - IP-in-IP (IPIP)
    - GRE
    - VXLAN
  - Does a tunnel by itself encrypt the traffic? Why?
- SSH Tunneling
  - Explain the differences between the following types of SSH tunnels, and give a use case for each one:
    - Local port forwarding (`ssh -L`)
    - Remote port forwarding (`ssh -R`)
    - Dynamic port forwarding (`ssh -D`)
  - What is a SOCKS proxy?
  - What is a jump host? How does `ssh -J` work?
- VPN
  - What is a VPN? What problems does it solve?
  - Explain the differences between a Site-to-Site VPN and a Remote Access (Client-to-Site) VPN
  - What is "Split Tunneling"? What are its pros and cons?
  - IPsec
    - What are the main components of IPsec? (IKE, ESP, AH)
    - What are the differences between ESP and AH?
    - What are the differences between Transport mode and Tunnel mode?
    - Why does IPsec have a problem with NAT, and what is NAT-T?
  - Read about OpenVPN and WireGuard
    - What transport layer protocol does each of them use by default, and on which port?
    - How is authentication done in each of them?
    - What are the main differences between them?
  - What is the difference between a `tun` and a `tap` interface in Linux?

### Exercise
- Create 2 vagrant machines, we'll refer to them as 'server1' and 'server2'
- SSH Tunneling
  - Run a web server on server2 that listens only on `127.0.0.1`. Using a local SSH tunnel, access it from server1
  - Using a remote SSH tunnel, make a service that runs on server1 reachable from server2
  - Open a dynamic SSH tunnel and use it as a SOCKS proxy with `curl`
- GRE Tunnel
  - Using the `ip` command, create a GRE tunnel between server1 and server2. Give each side of the tunnel an address from a new subnet (for example `10.100.100.0/30`)
  - Make sure you can `ping` between the tunnel addresses
  - Sniff the traffic on the physical interface with `tcpdump`, and identify the outer and inner IP headers
  - What is the MTU of the tunnel interface? Why is it different from the physical interface MTU?
- VPN
  - Deploy a WireGuard VPN between server1 and server2
  - Make sure you can reach server2 through the VPN tunnel
  - Sniff the traffic on the physical interface with `tcpdump`. Can you see the content of the packets? Compare it to the GRE tunnel
  - Extra: Route all of server1's traffic through server2 (full tunnel). What else needs to be configured on server2 for it to work? (Hint: think about forwarding and NAT)
